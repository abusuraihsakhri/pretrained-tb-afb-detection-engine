WORKFLOW

From slide image to reviewed detections.

The repository separates data preparation, model development, inference, post-processing, and expert review so each stage can be inspected and reproduced independently.

  1. 01
    Prepare and audit microscopy data

    Record source provenance and check images, labels, duplicates, and split boundaries.

  2. 02
    Develop the detector

    Run the model workflow only after dataset preflight succeeds; keep training and development validation distinct from a locked test.

  3. 03
    Analyze images or slides

    Run raster inference or tiled whole-slide analysis for larger image formats.

  4. 04
    Post-process detections

    Confidence filtering and global NMS consolidate candidate detections across overlapping regions.

  5. 05
    Review and curate

    Annotations enter a review queue for curator checks and group-safe split assignment.

LIMITATIONS

What this work does not establish.

  • AFB appearance does not identify Mycobacterium tuberculosis or confirm tuberculosis.
  • The historical metrics do not represent independent test performance; a corrected model has not completed locked-test evaluation.
  • No prospective, external-site, reader, workflow, calibration, or clinical-impact validation has been completed.
  • Performance across laboratories, scanners, staining protocols, populations, and low-load specimens remains unknown.
  • Smear grading requires a validated acquisition and field-sampling protocol; detections alone are insufficient.
  • The local research log is not a regulated electronic-record audit trail.

OPEN SOURCE

Designed for transparent, reproducible development.

The repository contains code for data preparation, training, inference, post-processing, API access, and annotation workflows. The results and limitations above describe the current evidence; the software is a research tool, not a standalone diagnostic system.
